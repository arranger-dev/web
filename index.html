Arrange agents.
Ship verified work.

Build a team of AI coding agents the way you'd build a real one: managers who split the work, workers who do it, reviewers who check it. You give the top agent one goal and a definition of done. Nothing counts as done until the checks pass.

why a hierarchy

Orchestration you don't have to babysit

One agent with one huge prompt drifts, forgets and claims success. A team with small, checked goals doesn't, because each layer only has to get one thing right and prove it.

One goal in, a plan out

Describe the outcome once. A manager gives each agent a subgoal, and every subgoal comes with a check that proves it.

goal teams with email invites ├ DB schema ✓ make migrate-check ├ Invites API ✓ go test ./invites/... └ Invite emails ✓ go test ./email/...
3tries

Checks decide "done", not the agent

Arranger runs your checks after every attempt and sends failures back. After three misses, it stops and asks you.

Parallel and isolated

Each agent works on its own git branch, at the same time as the others. Your branch is never touched.

main untouched ├ arranger/db-schema ├ arranger/invites-api └ arranger/invite-emails

Review before anything merges

Managers read every diff and accept it or send it back. One agent's mistake never reaches the rest.

✓ accepted DB schema ✗ sent back Invites API "expire invites after 7 days" ✓ accepted Invite emails

Small contexts, fewer hallucinations

Each agent sees only what it needs. Short, focused prompts are where agents are most reliable.

sees its own goal its manager's goal skips everyone else's work

You stay in control

Watch every agent live, and step in anywhere.

  • Live logs and status per agent
  • A diff for every agent
  • Request changes in one message
  • Remove, promote or revert any change
  • Token limits per agent
  • One-click merge into any branch
how it works

From goal to merged branch

  1. Arrange

    Drag agents into a tree. Pick a tool for each one and save the team as a project on your repo.

  2. Set the goal

    Give the top agent the outcome, acceptance criteria, and checks like go test ./....

  3. Run

    Managers plan, workers build, checks gate, reviewers accept or send work back. Watch it live.

  4. Request changes

    Not quite right? Tell the top manager what to change, once. Only the agents it concerns re-run, keeping their work.

  5. Merge

    Review the final diff, drop what you don't want, and merge into main or any branch.
